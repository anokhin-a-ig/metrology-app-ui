# Spec Delta

## ADDED Requirements

### Requirement: Создание департамента из каталога

Система SHALL предоставлять на странице «Департаменты» кнопку «Новый», которая открывает модальное окно с полями «Название», «Тип» и «Входит в состав», а также кнопками «Добавить» и «Отмена».

#### Scenario: Открытие окна создания

- **WHEN** пользователь нажимает кнопку «Новый»
- **THEN** открывается модальное окно создания департамента с пустыми полями

#### Scenario: Внешний вид кнопок

- **WHEN** модальное окно открыто
- **THEN** кнопка «Добавить» отображается зелёной, а кнопка «Отмена» — красной

#### Scenario: Отмена создания

- **WHEN** пользователь нажимает «Отмена»
- **THEN** модальное окно закрывается, а запрос на создание не отправляется

### Requirement: Выбор типа и родительского департамента

Система SHALL делать поле «Входит в состав» обязательным для типов `WORKSHOP`, `AREA` и `LABORATORY`, а для `FACTORY` очищать и блокировать его. Поле SHALL поддерживать поиск по части имени.

#### Scenario: Выбор типа FACTORY

- **WHEN** пользователь выбирает тип `FACTORY`
- **THEN** поле «Входит в состав» очищается и становится недоступным

#### Scenario: Выбор дочернего типа

- **WHEN** пользователь выбирает `WORKSHOP`, `AREA` или `LABORATORY`
- **THEN** поле «Входит в состав» становится доступным и обязательным

#### Scenario: Поиск родителя по части имени

- **WHEN** пользователь вводит часть названия в поле «Входит в состав»
- **THEN** система показывает департаменты, чьё название содержит введённый текст без учёта регистра

#### Scenario: Выбор родителя из списка

- **WHEN** пользователь выбирает департамент из результатов поиска
- **THEN** выбранное название отображается в поле и используется как родитель при создании

### Requirement: Валидация формы создания

Система SHALL не отправлять запрос, пока не заполнены обязательные поля, и SHALL показывать сообщения об ошибках рядом с соответствующими полями.

#### Scenario: Пустое название

- **WHEN** пользователь нажимает «Добавить» с пустым названием
- **THEN** запрос не отправляется, а под полем «Название» показывается ошибка

#### Scenario: Не выбран тип

- **WHEN** пользователь нажимает «Добавить», не выбрав тип
- **THEN** запрос не отправляется, а под полем «Тип» показывается ошибка

#### Scenario: Не выбран родитель для дочернего типа

- **WHEN** выбран тип `WORKSHOP`, `AREA` или `LABORATORY` и родитель не выбран
- **THEN** запрос не отправляется, а под полем «Входит в состав» показывается ошибка

### Requirement: Обработка результата создания

Система SHALL закрывать окно после успешного создания, показывать сообщение об успехе и обновлять дерево департаментов. При ошибке сервера окно SHALL оставаться открытым с введёнными данными и сообщением об ошибке.

#### Scenario: Успешное создание завода

- **WHEN** сервер создал департамент типа `FACTORY`
- **THEN** окно закрывается, показывается сообщение об успехе, а текущая страница корневого списка перезагружается

#### Scenario: Успешное создание дочернего департамента

- **WHEN** сервер создал департамент с родителем
- **THEN** окно закрывается, показывается сообщение об успехе, а ранее загруженные страницы детей этого родителя перезагружаются

#### Scenario: Дубликат названия

- **WHEN** сервер вернул ошибку о существующем названии
- **THEN** окно остаётся открытым, введённые данные сохраняются, а сообщение об ошибке отображается в окне

#### Scenario: Ошибка поиска родителя

- **WHEN** запрос поиска родительских департаментов завершился ошибкой
- **THEN** в выпадающем списке показывается сообщение об ошибке и возможность повторить поиск
