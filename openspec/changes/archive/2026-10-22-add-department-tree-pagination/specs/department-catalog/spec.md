# Spec Delta

## MODIFIED Requirements

### Requirement: Отображение списка департаментов

Система SHALL отображать департаменты в виде таблицы со столбцами: Название, Тип, Родительское подразделение.

#### Scenario: Загрузка списка департаментов

- **WHEN** пользователь открывает страницу «Департаменты»
- **THEN** система запрашивает данные и отображает таблицу с департаментами типа `FACTORY`

#### Scenario: Родительское подразделение у корневого департамента

- **WHEN** департамент отображается в корневом списке
- **THEN** в колонке «Родительское подразделение» показан прочерк «—»

### Requirement: Древовидная структура

Система SHALL отображать департаменты в виде дерева. При загрузке видны только департаменты стартового уровня. Узел с дочерними департаментами показывает кнопку раскрытия; дочерние департаменты загружаются при первом раскрытии и отображаются с отступом. Повторное нажатие сворачивает узел.

#### Scenario: Раскрытие узла

- **WHEN** пользователь нажимает на кнопку раскрытия рядом с департаментом
- **THEN** система загружает дочерние департаменты и отображает их с отступом

#### Scenario: Сворачивание узла

- **WHEN** пользователь нажимает на кнопку сворачивания раскрытого департамента
- **THEN** система скрывает дочерние департаменты

#### Scenario: Раскрытие узла любого типа

- **WHEN** пользователь раскрывает департамент типа `WORKSHOP`, `AREA` или `LABORATORY`
- **THEN** система отображает его дочерние департаменты с отступом

#### Scenario: Повторное раскрытие узла

- **WHEN** пользователь повторно раскрывает ранее раскрытый и свёрнутый департамент
- **THEN** система показывает ранее загруженные дочерние департаменты без нового запроса

#### Scenario: Узел без дочерних департаментов

- **WHEN** у департамента нет дочерних департаментов
- **THEN** кнопка раскрытия для него не отображается

## ADDED Requirements

### Requirement: Стартовый уровень каталога

Система SHALL определять стартовый уровень каталога по типу департамента `FACTORY`, а не по отсутствию родителя.

#### Scenario: FACTORY с родителем

- **WHEN** департамент типа `FACTORY` имеет родительский департамент
- **THEN** он всё равно отображается в корневом списке

### Requirement: Пагинация корневого списка

Система SHALL загружать департаменты стартового уровня постранично с сервера, по 10 элементов на страницу, и предоставлять навигацию по страницам.

#### Scenario: Переход на другую страницу

- **WHEN** пользователь выбирает страницу 2 в навигации
- **THEN** система запрашивает вторую страницу и заменяет строки таблицы

#### Scenario: Последняя страница

- **WHEN** пользователь находится на последней странице
- **THEN** переход к следующей странице недоступен

### Requirement: Постраничная загрузка дочерних департаментов

Система SHALL загружать дочерние департаменты страницами по 10 и показывать кнопку «Показать ещё», пока существует следующая страница.

#### Scenario: Загрузка следующей страницы дочерних

- **WHEN** пользователь нажимает «Показать ещё» под раскрытым узлом
- **THEN** система добавляет следующую страницу дочерних департаментов к уже показанным без дублей

#### Scenario: Дочерние загружены полностью

- **WHEN** загружена последняя страница дочерних департаментов
- **THEN** кнопка «Показать ещё» скрыта

### Requirement: Сортировка департаментов

Система SHALL отображать департаменты внутри списка в алфавитном порядке по названию по возрастанию.

#### Scenario: Порядок департаментов

- **WHEN** система отображает корневой список или дочерние департаменты
- **THEN** строки упорядочены по названию по возрастанию

### Requirement: Легенда над таблицей

Система SHALL отображать над таблицей легенду с русскими названиями типов департаментов и подсказкой о раскрытии иерархии.

#### Scenario: Отображение легенды

- **WHEN** пользователь открывает страницу «Департаменты»
- **THEN** над таблицей видны названия «Завод», «Цех», «Участок», «Лаборатория» и подсказка о кнопке «+»

### Requirement: Индикация загрузки

Система SHALL показывать индикацию загрузки, пока данные департаментов не получены.

#### Scenario: Загрузка корневого списка

- **WHEN** выполняется запрос корневого списка
- **THEN** в области таблицы отображается индикатор загрузки

#### Scenario: Загрузка дочерних департаментов

- **WHEN** выполняется запрос дочерних департаментов
- **THEN** под раскрываемым узлом отображается строка «Загрузка…»

### Requirement: Пустые состояния

Система SHALL показывать сообщение об отсутствии данных, когда запрос вернул пустой список.

#### Scenario: Пустой корневой список

- **WHEN** сервер вернул пустой список департаментов стартового уровня
- **THEN** система показывает «Департаменты не найдены»

#### Scenario: Нет дочерних департаментов

- **WHEN** сервер вернул пустой список дочерних департаментов
- **THEN** система показывает «Нет дочерних подразделений»

### Requirement: Ошибка загрузки корневого списка

Система SHALL показывать сообщение об ошибке и возможность повторить запрос, если корневой список не удалось загрузить.

#### Scenario: Повтор после ошибки

- **WHEN** запрос корневого списка завершился ошибкой и пользователь нажал «Повторить»
- **THEN** система повторно запрашивает корневой список

### Requirement: Ошибка загрузки дочерних департаментов

Система SHALL показывать ошибку внутри раскрытого узла и не скрывать остальные строки таблицы.

#### Scenario: Ошибка дочерних не ломает таблицу

- **WHEN** запрос дочерних департаментов завершился ошибкой
- **THEN** ошибка и кнопка «Повторить» отображаются внутри узла, а остальные строки остаются видимыми
